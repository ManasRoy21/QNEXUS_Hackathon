# Backend experiment engine

The backend now connects actual Qiskit measurements to the canonical protocol-distribution workflow and supports durable, repeated-trial studies. It remains a four-state channel/distribution research model; it does not establish a complete QDS signature-security proof.

## Execution pipeline

1. Choose reproducible Alice bits and X/Z preparation bases, plus independent receiver bases.
2. With `measurement_backend=qiskit_aer`, group identical single-qubit preparations, receiver bases and Eve bases. Execute Qiskit Aer density-matrix circuits with individual shot memory. Assign actual returned outcomes back to their pulse positions.
3. Sample fiber erasure, detector efficiency, and dark-count events externally with NumPy. A signal arrival takes priority over a simultaneous dark event. If only a dark event clicks, assign a random detector bit.
4. Sift clicks whose receiver/preparation bases match. The results are full conclusive bit registers, not aggregate error-rate estimates substituted for measurements.
5. Uniformly select test bits without replacement, keeping retained bits separate. Compute actual test and audit-only retained error rates.
6. Apply a one-sided Serfling sampling bound to the retained mismatch fraction. The two per-verifier error probabilities sum to the requested joint sampling-failure budget.
7. Save canonical state, measurements, execution versions, simulator seeds, transcript fingerprint and parameter-estimation evidence in SQLite.

For `numpy`, the same postprocessing uses a fast statistical signal-error approximation. The existing workflow UI defaults to Aer; the API default stays NumPy for compatibility. The API rejects unknown backend names, non-finite physics values, oversized circuit jobs, and oversized experiment budgets.

### Interception

An Eve Z-basis measurement/resend, averaged over outcomes, is equivalent to a dephasing channel: apply I with probability `1-f/2` and Z with probability `f/2`. Conjugating with H implements Eve's X basis. Eve's basis is independently chosen per pulse.

Before erasure/detector sampling, expected matched-basis error is:

`e_signal = e0 + (1 - 2e0) * f/4`

Conditioning on a click in this model gives:

`e_click = (p_arrival * e_signal + (1-p_arrival) * p_dark * 0.5) / p_click`

The expectation is displayed as a reference. Observed outcomes are generated by Qiskit on the Aer path. Tests force sampler outcomes to contradict the analytic prediction and verify that the engine follows the outcomes.

For an Aer-generated canonical state, `/simulation/attack` now re-executes intercept/resend with the requested fraction. It saves a separate attack run and leaves the baseline intact. It does not use the legacy algebraic QBER increment. Forgery and repudiation are explicitly unavailable on the new Aer path, rather than presenting unvalidated bounds from correlated samples. Older NumPy analyses remain for compatibility and are separate from this measured experiment engine.

## Parameter estimation

Given a conclusive register of size `N`, a uniform test subset of size `n`, and observed test error `e_test`:

`upper_remaining = min(1, e_test + N/(N-n) * sqrt((1 - (n-1)/N) * ln(1/epsilon) / (2n)))`

This follows by using Serfling to bound the population mean, then relating the population, test, and retained means. It is a mismatch sampling bound, not an authentication, forgery, or non-repudiation theorem.

- `PASS`: retained-error upper bound is below the configured policy.
- `SAMPLE_REJECT`: observed test error already exceeds the configured policy.
- `INCONCLUSIVE`: observed test error is below policy, but its uncertainty is too large to certify retained errors.
- `NO_DATA`: no usable test or retained register; undefined rates are `null` in this evidence object.

The legacy top-level canonical QBER field is still numeric for compatibility. A zero there with no conclusive bits is not a pass; consumers must use the new explicit estimation decision. Audit retained QBER is simulation ground truth used to validate sampling, not an extra observation a real remote verifier would automatically possess.

## Durable background studies

`POST /api/v1/experiments` returns HTTP 202. One local worker executes bounded trials off the API event loop. SQLite commits each trial, its canonical state, and progress in one transaction. Browsers can poll progress without waiting on the entire computation.

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/v1/experiments` | Queue a validated study; optional `Idempotency-Key` prevents duplicate submissions |
| GET | `/api/v1/experiments` | List saved studies |
| GET | `/api/v1/experiments/{id}` | Progress, status, summary |
| POST | `/api/v1/experiments/{id}/cancel` | Stop after the current trial; retain completed evidence |
| POST | `/api/v1/experiments/{id}/replay` | Re-run stored parameters and seeds |
| GET | `/api/v1/experiments/{id}/export` | Full JSON including every recorded trial |
| GET | `/api/v1/experiments/{id}/export.csv` | One row per trial/verifier with separate trial and verifier decisions |
| GET | `/api/v1/runs` | List saved canonical runs |
| GET | `/api/v1/runs/{id}` | Load a full run after refresh or API restart |

Statuses: `queued`, `running`, `completed`, `cancelled`, `interrupted`, `failed`. Process startup marks abandoned queued/running jobs interrupted; replay explicitly starts a fresh run. Failed jobs retain earlier trial records and expose an error rather than synthetic success.

The queue is capped at six pending/running studies, each with at most 64 trials and two million requested pulses. Individual Aer runs are capped at 100,000 pulses. Batching reports the actual Aer shot count, including surplus outcomes discarded because batch groups have unequal sizes.

Default storage is `backend/.data/qds.sqlite3`, ignored by Git. Override `QDS_DATABASE_PATH` with a writable persistent path. Use **one API process** for this local executor. This is not a distributed job queue, authenticated multi-user service, or horizontally scaled worker system. The existing image receipt key lifetime is independent of SQLite persistence.

## Reading a study

The engine reports per-point observed QBER, expected QBER, descriptive spread, rejected/passed/inconclusive counts, rejection rate and a Wilson interval across repeated trials.

For a no-interception point, rejection is counted as a false alarm. For an intercepted point, a `PASS` is counted as a missed attack. Inconclusive trials are reported separately and remain in all-trial rate denominators. Rejection is an error-policy decision; it does not identify an adversary, because honest noise can cause the same outcome.

Repeats use separate seeds. Corresponding sweep points share preparation/loss seeds for paired comparisons. Qiskit measurement streams and grouping can differ across attack settings, so this is not a claim that every draw is shared. Replay fingerprints bind the model, parameters and deterministic evidence, excluding only human labels, UUIDs, times and durations. The fingerprint is not a signature or a hardware-execution attestation.

The new UI is `/experiments`. The six-step workflow now exposes Aer/NumPy selection and no longer substitutes invented material or invented protocol entries when the API is offline.

## Message signing backed by Python

The old workflow's signing buttons only toggled frontend flags, reused a stale generation-time digest after message edits, and always displayed successful authentication. They have been replaced with real backend operations:

- `POST /api/v1/runs/{id}/sign-message`: hash the current UTF-8 message and create an Ed25519 signature over that hash, the saved run ID, transcript hash, and configuration/estimation/execution hash.
- `POST /api/v1/verify-message`: validate the issuer signature, hash the actual candidate message, reload the durable run, check its evidence binding, and apply both recorded sampling decisions.

A changed message returns `MESSAGE_CHANGED`. An edited receipt returns `UNTRUSTED_RECEIPT`. Changed saved evidence returns `EVIDENCE_CHANGED`. A valid message and signature cannot override insufficient or rejected channel evidence. The UI displays the server result and can download the receipt.

This is classical authenticated experiment evidence. It does not consume a QDS one-time register or derive the Ed25519 key from simulator measurements. Both verifier views run on the same backend. Issuer-key lifetime follows the existing `IMAGE_LAB_SIGNING_KEY` setting; SQLite persistence does not make an ephemeral key persistent.
