# Suggested six-slide pitch

1. **Problem:** Tiny image edits can be hard to notice; quantum-security demonstrations can be hard to interpret.
2. **Product:** QDS Lab — an image-integrity lab with a reproducible quantum-channel experiment.
3. **Live demo:** Pristine pass → one-pixel edit fails → intact image with intercepted channel fails for a different reason.
4. **Engineering:** Next.js, FastAPI, Pillow, SHA-256, Ed25519, Qiskit Aer; signed and downloadable evidence.
5. **Scientific evidence:** Actual counts, expected QBER, seed, shot count, assumptions, circuit, tested failure modes. Show measured results from your own run.
6. **Audience and next step:** Quantum-communication education and experiment prototyping. Future work: validated full protocol integration and authenticated multi-party deployment.

Use [the demo runbook](hackathon-demo.md). Do not claim quantum advantage, production security, universal detection accuracy, or a full QDS implementation.
